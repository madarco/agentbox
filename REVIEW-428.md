No blocker; reads are pure (confirmed no file written) and legacy names/meanings are preserved. Fix 1, 2, 3, 5 now (cheap, Phase 2 walks into them); 6, 7, 8 cheap too; 4 as a backlog line for Phase 3. No SDK republish needed for this PR (structural use only).

1. **A stale/skewed writer deletes other processes' rows (confirmed).** `packages/sandbox-core/src/llm-accounts.ts:119`, `:134-143`: `mutateAccounts` writes back `readAccounts(o)`, already filtered by `accept` against `o.specs` (default `AGENT_SYNC_SPECS`, frozen at module load). Long-lived hub + later `agent add foo` + a `foo` account from the CLI -> the hub's next mutation drops `foo`'s rows (secrets orphaned). Same for an older CLI/hub seeing a newer kind. Fix: filter only the returned view; on write pass through raw rows this process can't validate and only replace/delete the rows being changed; default specs to `currentAgentSpecs()`.
2. **Corrupt `accounts.json` loses every named account on the next mutation (confirmed).** `llm-accounts.ts:98-108`: `readRaw` maps SyntaxError (and wrong shape `[]`/`null`/future `version: 2`) to undefined, then the mutation writes only legacy defaults + the new row. Fix: reads stay lenient; mutations refuse (throw with the path) or rename to `accounts.json.corrupt-<ts>` first; better, rebuild missing rows from existing `credentials/<agent>/<id>.json` files.
3. **`writeAccountSecret(agent,'default',…)` is an unguarded writer of the legacy login (confirmed).** `llm-accounts.ts:220-233` writes straight to `credential.hostBackup`, skipping `realShape` and claude's newest-wins `shouldAcceptCredentialUpdate` (`sandbox-core/src/sync/concerns/credentials.ts:244`) — an older claude blob kills the login for every holder (Phase 0). Repro: expiresAt 100 accepted over 200; a pasted setup-token blob overwrites the real login and `default` vanishes. Fix: refuse `default` here (route through `writeCredentialBackup` + `shouldAcceptCredentialUpdate`), and for any `login`-kind write require `isRealCredentialShape` + the freshness gate (the Phase 4 fan-out will need it for named accounts).
4. **`prune --all` will reap per-account docker volumes (Phase 3).** `packages/sandbox-docker/src/lifecycle.ts:~895-925`: `expectedVolumes` = base `spec.dockerVolume` + surviving boxes' volumes; `agentbox-claude-config-acct-work` matches the `agentbox-` prefix. Add a backlog line: Phase 3 adds `accountConfigVolume(spec.dockerVolume, a.id)` for every `readAccounts()` row to the expected set.
5. **Reserved custody segment checked on the wrong field (confirmed by reading).** `packages/agent-registry/src/plugin-agents.ts:144-148` checks the basename of `boxAbsPath`, but custody paths use `credential.boxRelPath` (`relay/src/credentials-fanout.ts:121`, `hub-worker.ts:85`, `custody-client.ts:299`), which isn't validated. `boxRelPath: 'accounts/work'` passes and collides with named account `work`. Fix: validate `boxRelPath` (relative, no `..`, first segment not `accounts`).
6. **Plugin agent `id` not path-safe (low).** `accountSecretPath` (`core/src/sync/llm-accounts.ts:120`) joins `spec.id`; `agentSpecProblem` only checks non-empty, so `../../x` escapes `~/.agentbox/credentials/`. Add a slug regex (reuse `ACCOUNT_ID_RE`-style).
7. **Existing credentials dir with loose mode never tightened (low).** `llm-accounts.ts:123` `mkdir({recursive, mode:0o700})` only sets mode on creation; chmod `dirname(path)` and `credentials/` to 0700 after.
8. **Small:** canonicalize alias rows on read (`claude-code` -> `claude`) before de-dup; `writeAtomic` tmp name `${pid}.${Date.now()}` can collide -> `randomUUID()`; `withFileLock` proceeds unlocked after 20 s (shared behaviour, note it); `agent add` could refuse a plugin `dockerVolume`/`cloudSubpath` containing `-acct-`.
