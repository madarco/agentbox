# OpenClaw hosting — implementation plan

Status: **not started**. This is the durable plan doc; update the phase status lines as work
lands. One session per phase.

> **The agent catalog it depends on now exists** — see [`agents.md`](./agents.md). OpenClaw
> is the first agent that must NOT be hand-baked into `Dockerfile.box`. It is an
> `AGENT_SYNC_SPECS` row with an `npm` install recipe, installed on demand — see Phase 1
> below.

---

## Context

AgentBox today hosts **coding agents** (claude/codex/opencode): short-lived, interactive,
git-backed, one TUI per box. We want it to also host **OpenClaw** — an always-on
multi-channel AI gateway (`npm i -g openclaw`, MIT, `github.com/openclaw/openclaw`,
docs at `https://docs.openclaw.ai`).

That is a different workload in three ways:

1. **It is a daemon, not a TUI.** A single long-running Gateway on port `18789`
   multiplexing HTTP + WebSocket + a Control UI + `/healthz` / `/readyz` / `/startupz`.
   Boxes must *run* it, not just have it installed.
2. **Its "workspace" is the project.** OpenClaw's agent workspace (`AGENTS.md`, `SOUL.md`,
   `USER.md`, `MEMORY.md`, `memory/YYYY-MM-DD.md`, `skills/`) defaults to
   `~/.openclaw/workspace` but is relocatable via `OPENCLAW_WORKSPACE_DIR` — so we point it
   at `/workspace` and the user's project dir *becomes* the OpenClaw workspace. Its config
   (`~/.openclaw/openclaw.json`, JSON5 despite the extension) must be an AgentBox-owned
   **base** plus **additions from `agentbox.yaml`** (channels, models, plugins).
3. **OpenClaw users don't use git.** A non-git workspace today gets no `.git` bind mount, no
   `agentbox/<name>` branch, and no `git push --host-only` (see
   `packages/sandbox-core/src/git-detect.ts` and the `repos.length === 0` branch in
   `packages/sandbox-docker/src/create.ts`). `agentbox download` is the *only* way changes
   get back to the host — and on cloud providers that path is currently a bulk overwrite
   with no dry-run and no change list. That gap has to close.

Nothing named `openclaw`/`clawdbot`/`moltbot` exists in the repo today.

### Decisions taken

| Decision | Choice |
|---|---|
| CLI shape | New agent kind — `agentbox openclaw` |
| Providers, phase 1 | **docker + hetzner** |
| Box→host sync | Extend the existing `agentbox download` for non-git workspaces |
| Secrets | Non-secret config + SecretRef stubs in `agentbox.yaml`; real values in a carried 0600 `~/.openclaw/.env` |

**Why hetzner and not e2b/vercel:** a gateway holding live channel connections must be
always-on. E2B/Vercel microVMs auto-pause on a TTL (E2B Hobby caps a session at 1h) and
Daytona auto-stops — all fatal here. Hetzner is a real always-on VPS. The cost is no public
HTTPS URL: the Control UI arrives over the existing `ssh -O forward` `previewUrl`. That is
acceptable because every channel OpenClaw ships **dials out** (Telegram polling, WhatsApp
WebSocket) — no public inbound is required.

### Explicitly out of scope

OpenClaw is not a coding TUI, so we do **not** wire: session teleport, `--resume`/`-c`,
activity scrapers, skip-permissions flags, `-i` queue jobs, or the dashboard compositor
agent mode. This keeps the "4th agent kind" tail to the ~20 files that matter instead of the
~60 a full coding agent needs.

## Design shape

```
host project dir  ──create──▶  /workspace            ← OPENCLAW_WORKSPACE_DIR (the agent workspace)
                  ◀─download──                          AGENTS.md, SOUL.md, MEMORY.md, memory/, skills/

agentbox.yaml `openclaw:`  ─┐
baked base openclaw.json5  ─┼─▶ agentbox-ctl openclaw render ─▶ ~/.openclaw/openclaw.json
carried ~/.openclaw/.env   ─┘        (merge + AUTO_SECRET + validate)     (per-box volume)

ctl service `openclaw`  ─▶  openclaw gateway  :18789  ─expose as 80─▶  previewUrl / Portless
```

- **State is per-box, not shared.** Unlike claude/codex/opencode (one shared login volume
  across all boxes), an OpenClaw state dir carries a gateway identity and channel pairings.
  Two boxes must never share it. So `box.isolateOpenclawConfig` defaults to **`true`** — the
  inverse of the existing `isolate*Config` keys.
- **Two dirs to persist:** `~/.openclaw` (config, `state/openclaw.sqlite`,
  `agents/<id>/agent/openclaw-agent.sqlite`, `credentials/`) *and* `~/.config/openclaw`
  (auth-profile encryption key — deliberately not nested under the state dir).
- **Gateway auth is mandatory.** `gateway.bind` resolves to `0.0.0.0` inside a detected
  container, and OpenClaw refuses non-loopback binds without auth. Token is generated by
  `{{AGENTBOX_AUTO_SECRET:openclaw-gateway}}` and referenced as a SecretRef, so no plaintext
  token lands in `openclaw.json`.
- The Gateway also refuses to start unless `gateway.mode=local` is set (or
  `--allow-unconfigured`).

## Phase 0 — live PoC before any code

Validate the load-bearing assumptions by hand inside an existing docker box
(`agentbox claude --shared-docker-cache --carry-yes`), and record the results in this doc:

1. `npm i -g openclaw --allow-scripts=openclaw` succeeds on the box's Node. **Check the
   engine range** — OpenClaw requires `>=22.22.3 <23 || >=24.15.0 <25 || >=25.9.0` and
   `packages/sandbox-docker/Dockerfile.box:62` installs NodeSource `setup_24.x`; confirm the
   resolved 24.x is `>= 24.15.0`. ~87 MB unpacked, so measure the image-size delta.
2. Headless bootstrap works: `openclaw onboard --non-interactive --accept-risk --mode local
   --skip-channels --skip-health --no-install-daemon` (`--non-interactive` *requires*
   `--accept-risk`).
3. `OPENCLAW_WORKSPACE_DIR=/workspace` is honoured and does not fight the agent bootstrap
   files.
4. `openclaw gateway` binds `0.0.0.0:18789` in-container, `/healthz` answers, and the Control
   UI renders through the box's web proxy on port 80.
5. A hand-merged `openclaw.json` passes `openclaw config validate`, and `openclaw channels
   add --channel telegram --use-env` works non-interactively.
6. Confirm which dirs must survive a restart by stopping/starting and re-checking pairing.

**Anything that fails here changes the phases below — do not skip.**

## Phase 1 — bake + register the agent kind (docker)

**Install — via the catalog, not a Dockerfile `RUN`.** Per
[`agents.md`](./agents.md) → "Adding a new agent", OpenClaw is one registry row:

```ts
install: {
  placement: 'ondemand',
  probe: 'openclaw',
  recipe: { kind: 'npm', package: 'openclaw', allowScripts: true },
  postInstall: 'mkdir + chown ~/.openclaw ~/.config/openclaw',
}
```

`allowScripts` is load-bearing: the package has `preinstall`/`postinstall` lifecycle scripts
that npm 12 blocks by default, and a degraded install is the result. It installs on demand
(docker *and* hetzner) and is optionally baked into a base variant
(`--agents claude,codex,opencode,openclaw`) once the variant path exists.

Still needed regardless of placement, since these are box-layout concerns rather than an
install step:

- `~/.agentbox-creds/openclaw/` + the credential symlink, mirroring `Dockerfile.box`
  lines 237–253.
- `~/.openclaw` and `~/.config/openclaw` created and `chown`ed — `vscode`'s uid varies per
  provider, so `chown vscode:vscode`, never `1000`.
- Any new baked *asset* (e.g. `openclaw-base.json5`, Phase 2) goes through the collapsed
  asset manifest — today that means `apps/cli/scripts/stage-runtime.mjs`
  (`contextFiles` + `execBitFiles`), `DOCKER_CONTEXT_FILE_MAP` and
  `packages/provider-sdk/src/runtime-assets.ts`.

**Register the kind** (the minimum set):

| File | Change |
|---|---|
| `packages/sandbox-core/src/sync/registry.ts` | New `AgentSyncSpec` row: box dirs, `sessionName`, `dockerVolume`, `staticPaths`, `credential`, `forwardedEnvKeys`, `caps: {resume:false, teleport:'none', activitySource:'none'}` |
| `packages/sandbox-core/src/sync/agents/types.ts` | Widen `AgentId` |
| `packages/core/src/sync/agent-kind.ts` | `SyncAgentKind`/`QueueAgentKind`/`SYNC_AGENT_KINDS`/`toSyncKind`/`toQueueKind`/`normalizeLastAgent` |
| `packages/core/src/box-record.ts` | `openclawConfigVolume`, widen `lastAgent` |
| `packages/sandbox-docker/src/sync/agents/openclaw.ts` | **New** — clone `opencode.ts` (smallest template, no plugin/setup-skill baggage) |
| `packages/sandbox-docker/src/{index.ts,create.ts,lifecycle.ts,provider-module.ts,sync/docker-sync.ts}` | Re-export, `wantOpenclaw` detection, mounts, volume allowlists, `seedAgentConfig` |
| `packages/config/src/types.ts` + `packages/config/schema/user-config.schema.json` | `openclaw.*` branch, `box.isolateOpenclawConfig` (**default `true`**) |

`agentbox openclaw` attaches to a tmux session running `openclaw tui --local` against the
box's own gateway — the interactive surface, distinct from the supervised daemon.

## Phase 2 — config composition (`openclaw:` in agentbox.yaml)

Do the merge **in-box**, in `@agentbox/ctl`, so it is provider-uniform and re-runs on
`agentbox-ctl reload` (the same escape hatch the setup wizard already uses).

- `packages/ctl/src/config.ts` — add `openclaw` to `TOP_LEVEL_KEYS` and parse it as an opaque
  mapping (ctl does not need OpenClaw's schema; `openclaw config validate` is the real gate).
  Unknown keys stay non-fatal warnings, per the existing contract.
- `packages/ctl/schema/agentbox.schema.json` + `packages/ctl/test/schema-drift.test.ts` — the
  drift test fails until both sides are updated.
- **New** `packages/ctl/src/commands/openclaw-render.ts` (`agentbox-ctl openclaw render`),
  reusing existing primitives rather than new ones:
  - `resolveAutoSecrets` (`packages/ctl/src/secret.ts`) for
    `{{AGENTBOX_AUTO_SECRET:openclaw-gateway}}`, persisted 0600 at
    `/var/lib/agentbox/secrets/`.
  - `applyReplacements` + `placeholderContextFromEnv` (`packages/ctl/src/replace.ts`,
    `packages/core/src/replace.ts`) for `{{AGENTBOX_*}}` — the whitelist deliberately
    excludes secrets.
  - Deep-merge order: **baked base → `openclaw:` block → never clobber user edits made
    in-box through `openclaw config set`** (keep an agentbox-owned marker key so the render
    is idempotent).
  - Finish with `openclaw config validate`; fail the task loudly on a bad merge.
- **Baked base template** — a new runtime asset (`openclaw-base.json5`) staged like
  `opencode-agentbox-plugin.js`, holding AgentBox's defaults: `gateway.mode=local`,
  `gateway.port=18789`, token as an env SecretRef, `agents.defaults.workspace=/workspace`.
- **Secrets stay out of `agentbox.yaml`**: real values ride a `carry:` entry into
  `~/.openclaw/.env` at `mode: 0o600` (the existing `planCarryEntry` path in
  `packages/sandbox-core/src/sync/concerns/files.ts`), and the config references them as
  `{ source: 'env', id: ... }`. Add a lint that warns when a secret-shaped literal appears
  under `openclaw:`.

Authoring shape:

```yaml
openclaw:
  channels:
    telegram:
      botToken: { source: env, id: TELEGRAM_BOT_TOKEN }
carry:
  - src: ~/.openclaw-secrets.env
    dest: ~/.openclaw/.env
    mode: 0o600
```

## Phase 3 — run and expose the gateway

- The `openclaw` **service** is declared in the generated `agentbox.yaml`, with:
  - `command: openclaw gateway`, `needs: [openclaw-render]`, `restart: always`
  - `ready_when: { http: '/healthz', port: 18789 }` — `packages/ctl/src/probe.ts` already
    supports the http probe
  - `expose: { port: 18789, as: 80 }` — `as` must equal `RESERVED_WEB_PORT`, and at most one
    service may expose. This is what makes `agentbox url` / Portless
    (`https://<box>.localhost`) / the cloud `previewUrl` work with **no new machinery**.
- `agentbox openclaw token <box>` (or fold into `agentbox url`) to print the gateway token
  alongside the URL, since the Control UI needs it pasted in.
- Add the OpenClaw workspace/gateway shape to the setup skill
  (`apps/cli/share/agentbox-setup/SKILL.md` + the per-provider mirrors under
  `apps/cli/runtime/*/agentbox-setup-skill.md`) so a project without an `agentbox.yaml` gets
  a correct one generated.

## Phase 4 — `download` for non-git workspaces

Docker already degrades correctly: no `.git` → tar-pipe seed at create, and `pullToHost`
falls back to exclude-list mode. Two real gaps:

1. **Cloud has no gitignore-aware download, no `--dry-run`, no change list** — it is a bulk
   overwrite (`apps/cli/src/commands/download.ts` `isCloud` branch → `pullCloudDirContents`
   in `packages/sandbox-cloud/src/cloud-cp.ts`). Close it by reusing the *second half* of the
   docker path rather than writing a parallel one:
   - Lift stage 2 of `pullToHost` (`packages/sandbox-docker/src/sync/host-export.ts:446` —
     the host-side `rsync -a --checksum --files-from=- --from0` into `box.workspacePath`, plus
     `parseItemizedChanges`) into `@agentbox/sandbox-core` as a shared concern.
   - Cloud stage 1: compute the file list in-box (`git ls-files -z` when it is a repo,
     otherwise `find` with the exclude list), tar **only** those paths,
     `backend.downloadFile`, extract into the same host scratch dir docker uses.
   - Both providers then share stage 2 → `--dry-run` and the change list work on cloud for
     free, and `--no-respect-gitignore` / `--include-node-modules` / `--pattern` stop being
     silently ignored.
2. **Non-git exclude defaults.** In exclude-list mode add OpenClaw-aware excludes
   (`.openclaw/`, `media/`, `*.sqlite*`) so a stray in-workspace state dir never lands on the
   host. Surface `(exclude-list mode)` prominently — for these users it is the *normal* mode,
   not a fallback.
3. `agentbox download openclaw` — a new subcommand alongside `download claude|codex|opencode`
   (`packages/sandbox-core/src/sync/agent-pull.ts`, `agent-propagate.ts`,
   `packages/core/src/sync/files.ts` `DownloadKind`, and the relay allowlist in
   `packages/relay/src/host-actions.ts`) to pull `~/.openclaw` state (pairings, sqlite) back
   for backup/restore. Note the cloud relay currently answers
   `download.<kind> is not yet supported for cloud boxes` — that needs lifting for hetzner.

## Verification

Phase 0 is itself the first gate. After that — start slow commands in the background and tail
`~/.agentbox/logs/latest.log` rather than picking a blind timeout:

```sh
# docker
node apps/cli/dist/index.js openclaw -y -n claw-smoke &
tail -f ~/.agentbox/logs/latest.log            # wait for box ready + service ready

node apps/cli/dist/index.js status claw-smoke  # openclaw service == ready
node apps/cli/dist/index.js url claw-smoke     # Control UI over the web proxy
curl -fsS "$(… url …)/healthz"                 # ground truth, not an exit code

# config composition
#   edit agentbox.yaml `openclaw:` → agentbox-ctl reload → re-render → openclaw config validate

# non-git download round-trip (the whole point)
mkdir /tmp/claw-ws && cd /tmp/claw-ws          # no .git on purpose
node apps/cli/dist/index.js openclaw -y
#   … edit MEMORY.md / memory/*.md inside the box …
node apps/cli/dist/index.js download --dry-run # change list must be non-empty and correct
node apps/cli/dist/index.js download -y        # files land back in /tmp/claw-ws

# hetzner
node apps/cli/dist/index.js prepare --provider hetzner
node apps/cli/dist/index.js openclaw --provider hetzner -y -n claw-hz
#   same status/url/healthz/download checks
```

Unit tests: `pnpm test` (the registry cross-check, schema-drift, and runtime-assets tests
fail until updated — that is the intended forcing function). Then `pnpm typecheck` (tsup does
not typecheck, and CI runs it), and format only touched files with
`npx prettier --write <files>` — `pnpm format` rewrites ~530 unrelated files.

## Risks / things to confirm early

- **Node engine range.** OpenClaw excludes Node 23 and 25.0–25.8. The box is on NodeSource
  24.x; confirm `>= 24.15.0`. If not, the bake needs a pinned Node.
- **Image size.** `openclaw` alone is ~87 MB unpacked, before plugins. It shifts the
  build-context fingerprint, so every provider's base snapshot goes stale and the
  `box-image` CI tag moves.
- **`box.image` collides across providers** — a cloud `prepare` writing the generic project
  `box.image` breaks creates on other providers. Watch for it when re-preparing hetzner.
- **WhatsApp pairing is QR-only and interactive.** It works via the Control UI in a browser,
  but that means hetzner needs the SSH port-forward up during pairing. Token-based channels
  (Telegram/Discord, `channels add --use-env`) are fully scriptable and should be the
  documented default. The WhatsApp runtime is a separate plugin
  (`openclaw plugins install clawhub:@openclaw/whatsapp`), not in the core package.
- **Multi-tenancy.** OpenClaw explicitly does not support multiple tenants inside one
  Gateway — one box per tenant is the only correct model, which is what per-box state
  isolation enforces. Their own `openclaw fleet` is a host-side Docker supervisor and is
  marked experimental; we deliberately do not build on it.
- **Two schema halves.** `agentbox.yaml` is parsed by two independent hand-written parsers
  (`@agentbox/ctl` for `services`/`tasks`/`carry`/`replacements`, `@agentbox/config` for
  `defaults:`). The new `openclaw:` key belongs to the ctl half only.
